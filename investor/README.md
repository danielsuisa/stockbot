# בוט המשקיע (InvestorBot)

בוט טלגרם חינמי למחקר מניות אמריקאיות. הוא עושה שני דברים:

- **התראה יומית** כשכמה מנהלים ודירקטורים של אותה חברה קונים את המניה שלה בכסף שלהם, בשוק הפתוח.
- **דוח פורנזי בעמוד אחד** על כל מניה אמריקאית: מקיצור דרך באייפון או בהודעה לבוט.

הכול רץ בחינם על GitHub Actions (במאגר ציבורי), טלגרם ונתוני SEC EDGAR. אין שרת, אין תשלום ואין מפתחות API בתשלום.

**מה צריך:** חשבון GitHub (חינמי), טלגרם, אייפון (לקיצור הדרך) וכתובת אימייל. נוח יותר ממחשב, אבל אפשר גם מהטלפון בדפדפן (אם לשונית `Settings` לא מופיעה, עברו לתצוגת מחשב).

## התקנה ב־4 שלבים (כ־10 דקות)

### שלב 1: מעתיקים את הפרויקט לחשבון שלכם

- נכנסים ל־GitHub, פותחים את דף הפרויקט, לוחצים `Fork` ואז `Create fork`.
- המאגר צריך להישאר **ציבורי** (Public): כך GitHub Actions חינמי וללא הגבלה.
- רשמו לעצמכם את שם המשתמש ואת שם המאגר, כפי שהם מופיעים בכתובת: `github.com/USER/REPO`.
- אין כפתור `Fork`? צרו מאגר ציבורי חדש (`New repository`) והעלו אליו את כל הקבצים (`Add file` ואז `Upload files`), כולל התיקייה <code dir="ltr">.github</code> (במק היא מוסתרת; ב־Finder מציגים אותה בצירוף המקשים ⌘⇧.).

### שלב 2: יוצרים בוט בטלגרם

- בטלגרם מחפשים `BotFather` (עם וי כחול), נכנסים ולוחצים `Start`.
- שולחים לו <code dir="ltr">/newbot</code>, ונותנים שם לבוט (כל שם, למשל "המשקיע שלי").
- אחר כך הוא מבקש שם משתמש באנגלית שמסתיים ב־`bot`, למשל `savta_investor_bot`.
- בתשובה מגיע **טוקן**: מחרוזת ארוכה עם נקודתיים באמצע. העתיקו ושמרו אותו. זו הסיסמה של הבוט, אל תשתפו אותה.
- לוחצים על הקישור לבוט החדש, לוחצים `Start` ושולחים לו "שלום" (בוט לא יכול לפנות אליכם לפני שפניתם אליו).

### שלב 3: מחברים את הבוט ל־GitHub ומפעילים

**דרך מהירה, למי שיש טרמינל:** מתוך תיקיית הפרויקט במחשב מריצים `bash setup.sh`. הסקריפט מבקש את הטוקן, מוצא לבד את מזהה הצ'אט, שומר את שלושת הסודות (אם `gh` מותקן ומחובר) או מדפיס בדיוק מה להדביק, ושולח הודעת בדיקה. אחר כך ממשיכים לסעיף ג׳.

**דרך ידנית, בדפדפן בלבד:**

**א. מזהה הצ'אט.** מיד אחרי ששלחתם לבוט הודעה, פתחו בדפדפן את הכתובת הזו, כשבמקום `TOKEN` (כולל הסוגריים סביבו) מדביקים את הטוקן. המילה `bot` נשארת צמודה אליו:

<div dir="ltr">

```
https://api.telegram.org/bot<TOKEN>/getUpdates
```

</div>

בדף שנפתח מחפשים את `chat` ואחריו `id`. המספר שמופיע שם הוא מזהה הצ'אט (אם יש לפניו מינוס, גם הוא חלק מהמספר). כך זה נראה:

<div dir="ltr">

```
{"ok":true,"result":[{"update_id":…,"message":{…,"chat":{"id":987654321,"first_name":…
```

</div>

אם מופיע `result` עם סוגריים ריקים, שלחו לבוט עוד הודעה ורעננו את הדף.

**ב. שלושה סודות.** במאגר שלכם נכנסים ל־`Settings` → `Secrets and variables` → `Actions` ולוחצים `New repository secret`, שלוש פעמים, עם השמות האלה בדיוק:

| שם (Name) | ערך (Secret) |
|---|---|
| `TG_TOKEN` | הטוקן מ־BotFather |
| `TG_CHAT_ID` | מזהה הצ'אט מסעיף א׳ |
| `SEC_UA` | המילה `InvestorBot`, רווח, והאימייל שלכם. למשל: `InvestorBot you@example.com` (רשות ניירות הערך האמריקאית דורשת כתובת ליצירת קשר) |

**ג. מפעילים את האוטומציה.** פותחים את לשונית `Actions` במאגר:

- במאגר שנוצר ב־Fork לוחצים על הכפתור הירוק `I understand my workflows, go ahead and enable them`.
- ב־Fork גם התזמונים כבויים מראש: לוחצים ברשימה שבצד על `Daily insider scan`, ואם מופיע פס עם כפתור `Enable workflow`, לוחצים עליו. אותו דבר עבור `Telegram listener`.
- במאגר חדש (לא Fork) הכול כבר פעיל.

### שלב 4: קיצור דרך באייפון

**א. מפתח לקיצור הדרך** (טוקן של GitHub שמותר לו רק להפעיל את הבוט במאגר שלכם):

- פותחים את `https://github.com/settings/personal-access-tokens/new` (או: לוחצים על תמונת הפרופיל ומשם `Settings` → `Developer settings` → `Personal access tokens` → `Fine-grained tokens` → `Generate new token`).
- שם (`Token name`): למשל `iphone`. תוקף (`Expiration`): הארוך ביותר שמוצע. רשמו לעצמכם את התאריך.
- גישה (`Repository access`): בוחרים `Only select repositories` ומסמנים רק את המאגר שלכם.
- הרשאות (`Permissions`): מוסיפים את `Actions` וקובעים `Read and write`. לא צריך שום הרשאה אחרת.
- לוחצים `Generate token` ומעתיקים את הטוקן (מתחיל ב־`github_pat`). הוא מוצג פעם אחת בלבד.

**ב. הקיצור עצמו.** פותחים את אפליקציית קיצורים (`Shortcuts`), לוחצים על `+`, קוראים לקיצור "בדוק מניה" ומוסיפים שלוש פעולות לפי הסדר (מוצאים כל אחת בשורת החיפוש):

- **פעולה ראשונה:** `Ask for Input`. סוג הקלט `Text`, והשאלה: איזה טיקר?
- **פעולה שנייה:** `Get Contents of URL`.
  - בשדה הכתובת מדביקים את הכתובת שבמסגרת למטה, עם שם המשתמש והמאגר שלכם במקום `USER` ו־`REPO`. אם כבר כתוב בשדה `Provided Input`, מוחקים אותו קודם.
  - לוחצים על החץ הקטן (`Show More`) ובוחרים ב־`Method` את `POST`.
  - ב־`Headers` מוסיפים שתי כותרות (`Add new header`): הכותרת `Authorization` עם הערך `Bearer`, רווח והטוקן מסעיף א׳; והכותרת `Accept` עם הערך `application/vnd.github+json`.
  - ב־`Request Body` בוחרים `JSON` ומוסיפים שני שדות (`Add new field`):
    - שדה מסוג `Text` בשם `ref` עם הערך `main` (אם הענף הראשי במאגר נקרא אחרת, למשל `master`, כותבים את שמו).
    - שדה מסוג `Dictionary` בשם `inputs`. לוחצים עליו ומוסיפים בתוכו שדה `Text` בשם `ticker`, ובערך בוחרים את המשתנה `Provided Input` (מהשורה שמעל המקלדת).
- **פעולה שלישית:** `Show Notification` עם הטקסט: נשלח! הדוח יגיע לטלגרם בתוך כדקה

כך נראית הבקשה המלאה שהקיצור שולח (להשוואה):

<div dir="ltr">

```
POST https://api.github.com/repos/USER/REPO/actions/workflows/check.yml/dispatches
Authorization: Bearer github_pat_XXXXXXXXXXXX
Accept: application/vnd.github+json

{"ref": "main", "inputs": {"ticker": "<Provided Input>"}}
```

</div>

טיפ: דרך כפתור השיתוף של הקיצור אפשר להוסיף אותו למסך הבית, או פשוט לבקש מסירי "בדוק מניה". אין אייפון? שלחו לבוט את הטיקר בהודעה: באותיות גדולות (`AAPL`), עם דולר (`$aapl`), או כמילה יחידה בהודעה (`aapl`).

## בדיקה

- בלשונית `Actions` בוחרים ברשימה את `Check ticker`, לוחצים `Run workflow`, כותבים `AAPL` ולוחצים שוב על `Run workflow` הירוק. תוך 1–3 דקות מגיע דוח לטלגרם.
- וי ירוק ליד הריצה פירושו הצלחה. איקס אדום: לוחצים על הריצה ורואים מה נכשל (בדרך כלל סוד חסר או עם שגיאת כתיב בשם).
- מפעילים את קיצור הדרך באייפון ומקלידים `MSFT`. אחר כך שולחים לבוט בטלגרם `TSLA`: התשובה מגיעה תוך כ־10–20 דקות.
- מריצים ידנית פעם אחת את `Daily insider scan` באותה דרך. הריצה הראשונה סורקת 30 יום אחורה, נמשכת עד כשעה ועשויה לשלוח כמה התראות בבת אחת. מכאן והלאה היא רצה לבד.
- קיצור הדרך "הצליח" אבל לא נוספה ריצה ב־`Actions`? הוסיפו להודעה של `Show Notification` את המשתנה `Contents of URL`: אם מופיע בו `workflow_run_id` (או שהוא ריק), הבקשה הצליחה. `Bad credentials` פירושו טוקן שגוי או שפג תוקפו, `Not Found` פירושו כתובת שגויה, `No ref found` פירושו שם ענף שגוי, ו־`Resource not accessible` פירושו שחסרה הרשאת `Actions`.

## מה מקבלים

### ההתראה היומית

רצה בבקרים של ימים ג׳–ש׳ (05:30 UTC, בערך 07:30–08:30 שעון ישראל, לפעמים באיחור) על דיווחי יום המסחר הקודם, ומשלימה ימים שהוחמצו. נשלחת רק כשיש מידע חדש, כך שביום שקט לא תגיע הודעה. לכל חברה מופיעים:

- טיקר, שם החברה והסיבה: **אשכול רכישות** (לפחות 2 נושאי משרה או דירקטורים שונים קנו יחד בלפחות 100 אלף דולר ב־30 הימים האחרונים) או **רכישה גדולה** (דיווח בודד של חצי מיליון דולר ומעלה).
- מספר דיווחי הרכישה, מספר הרוכשים והסכום הכולל.
- עד 6 רכישות: שם, תפקיד, תאריך, סכום ומחיר ממוצע. הסימן 🆕 מציין דיווח שלא הופיע בהתראה קודמת.
- קישור לכל דיווחי בעלי העניין של החברה ב־EDGAR.

נספרות רק רכישות בשוק הפתוח (קוד `P` בטופס 4): לא מענקים, לא מימוש אופציות ולא מכירות.

### הדוח למניה

הודעה אחת עם:

- ענף החברה (`SIC`), השנים שהושוו (שני הדוחות השנתיים האחרונים) והכנסות, רווח, תזרים ונכסים.
- ציוני פיוטרוסקי, אלטמן ובנייש.
- רכישות בעלי עניין בשוק הפתוח ב־180 הימים האחרונים.
- השינויים בפרק גורמי הסיכון בין שני הדוחות השנתיים האחרונים.

כל מספר מגיע מ־EDGAR. נתון שלא נמצא מסומן "חסר" לצד שם התג ב־XBRL, ואף פעם לא מוחלף בהערכה.

### איך לקרוא את הציונים

- **פיוטרוסקי (F):** תשע בדיקות של בריאות פיננסית (רווחיות, תזרים, חוב, נזילות, דילול מניות, שולי רווח ויעילות). כל ✅ שווה נקודה; 8–9 חזק, 0–2 חלש. בדיקה שחסר לה נתון לא נספרת, ולכן הציון מוצג מתוך מספר הבדיקות שחושבו.
- **אלטמן (Z):** סיכון לקריסה פיננסית בשנתיים הקרובות. מעל 2.99 בטוח, בין 1.81 ל־2.99 אפור, מתחת ל־1.81 מצוקה. כשאין מחיר מניה או מספר מניות עדכני מחושבת גרסה לפי ההון בספרים (<code dir="ltr">Z''</code>): מעל 2.60 בטוח, מתחת ל־1.10 מצוקה.
- **בנייש (M):** האם הרווחים נראים "מיופים". מעל מינוס 1.78: סיכון גבוה; בין מינוס 2.22 למינוס 1.78: אזור ביניים; מינוס 2.22 ומטה: סיכון נמוך. בחברה רגילה שמונת המדדים שלצדו קרובים ל־1.
- **גורמי הסיכון (Lazy Prices):** רוב החברות כמעט לא משנות את נוסח הפרק משנה לשנה. אחוז שימור נמוך והרבה משפטים חדשים, ובמיוחד משפטים חדשים עם מילים כמו `going concern` או `material weakness`, הם סימן לבדוק לעומק.
- בבנקים, בחברות ביטוח ובשאר החברות הפיננסיות (SIC 6000–6799) אלטמן ובנייש לא מחושבים, כי המודלים לא מתאימים למאזן שלהן.

## כוונון (לא חובה)

משנים באותו מסך של הסודות (שלב 3, סעיף ב׳), בלשונית `Variables`, בכפתור `New repository variable`. כותבים מספרים בלבד, בלי פסיקים. משתנה שלא הוגדר מקבל את ברירת המחדל.

| משתנה | ברירת מחדל | משמעות |
|---|---|---|
| `MIN_INSIDERS` | 2 | כמה נושאי משרה או דירקטורים שונים נדרשים לאשכול |
| `MIN_CLUSTER_USD` | 100000 | הסכום הכולל המינימלי לאשכול, בדולרים |
| `MIN_SINGLE_USD` | 500000 | רכישה בודדת שמספיקה לבדה להתראה, בדולרים |
| `WINDOW_DAYS` | 30 | חלון הימים שבו מחפשים אשכולות |
| `MAX_CATCHUP` | 5 | כמה ימים שהוחמצו משלימים בריצה אחת |
| `INSIDER_DAYS` | 180 | כמה ימים אחורה מוצגות רכישות בדוח המניה |

## מגבלות ידועות

- **תזמון של GitHub:** ריצות מתוזמנות מתעכבות לפעמים (דקות ואף יותר משעה), ובעומס כבד גם מדלגות. ההאזנה לטלגרם רצה בערך כל 10 דקות, ולכן תשובה להודעה לוקחת 10–20 דקות. קיצור הדרך מהיר יותר.
- **כיבוי אחרי 60 יום בלי פעילות:** במאגר ציבורי ללא שינוי במשך 60 יום, GitHub מכבה את התזמונים. הסריקה היומית שומרת את `data/state.json` בכל בוקר, וזה שומר על המאגר פעיל. אם בכל זאת כובה, בוחרים אותו בלשונית `Actions` ולוחצים `Enable workflow`.
- **מחיר המניה מ־Yahoo:** מקור לא רשמי שעלול להיכשל. במקרה כזה אלטמן מחושב לפי ההון בספרים, והדוח אומר זאת.
- **תגי XBRL חסרים:** חברות מדווחות בתגים שונים. מה שלא נמצא מוצג כ"חסר" עם שם התג; חוב לזמן ארוך שלא דווח נחשב אפס, וגם זה נכתב בדוח.
- **רק דוחות שנתיים <code dir="ltr">10-K</code>:** חברות זרות שמגישות <code dir="ltr">20-F</code> או <code dir="ltr">40-F</code> לא נתמכות בדוח, ובהתראות הן מוזכרות בשם בלבד (המחירים בדיווח שלהן עשויים להיות במטבע מקומי). נתונים רבעוניים לא נכללים, כך שהמספרים עשויים להיות בני עד שנה.
- **פרק גורמי הסיכון** (Item 1A) מאותר לפי כותרות. בדוח בעיצוב חריג האיתור עלול להיכשל, וחברות קטנות פטורות לפעמים מהפרק.
- **מגבלות הקצב של SEC:** הבוט שולח עד 8 בקשות בשנייה ומנסה שוב אחרי חסימה. ריצה שנכשלה תושלם בריצה הבאה (עד 5 ימים אחורה).
- **תוקף הטוקן של קיצור הדרך:** כשהוא פג, הקיצור מפסיק לעבוד (GitHub שולח תזכורת במייל לפני כן). יוצרים טוקן חדש כמו בשלב 4 ומחליפים אותו בכותרת `Authorization`.
- **גם מניות מחוץ לבורסה:** רשימת הטיקרים של SEC כוללת גם מניות OTC, ולכן גם הן עשויות להופיע בהתראות.
- **עיכוב בדיווח:** לבעלי עניין יש 2 ימי עסקים לדווח, כך שההתראה מגיעה כמה ימים אחרי הקנייה עצמה. בדוח למניה נבדקים עד 150 הדיווחים האחרונים.
- **המאגר ציבורי:** הקוד ו־`data/state.json` (מידע ציבורי מ־EDGAR) גלויים לכולם, הסודות לא. אל תכתבו טוקן בשום קובץ.
- **פרטיות:** יומני הריצה (`Actions`) של מאגר ציבורי גלויים לכולם, כולל הטיקר שהזנתם בקיצור הדרך ומועד הבדיקה. הודעות הטלגרם עצמן ומזהה הצ'אט לא נרשמים ביומן.
- **עצירה:** בלשונית `Actions` בוחרים תהליך, ובתפריט `...` לוחצים `Disable workflow`.
