# ZBA v2 — implementation plan (spec section 14, approved 2026-10-09)

Goal: the 22 variants of section 14 on 2022-01-03 → 2026-10-08, the selection, the freeze, then one holdout run on
2016-01-04 → 2021-12-31. Stdlib only; keys only on GitHub (Actions secrets), so every data run happens there.

## Task 1 — ticket._zba options (TDD, `tests/test_zba_v2.py`)

ctx keys, all absent by default (K10s and every existing test unchanged):

| key | rule | NO TICKET reason |
|---|---|---|
| `candle` = (lo, hi, body) | #6 range / ATR in [lo, hi], body / range ≥ body | `candle` |
| `confirm` = k | #5 first minute from 09:35 closing beyond the level with volume ≥ k × mean minute volume 09:30 → m−1; entry at the next minute's open (`entry_type` `MKT`) | `trigger` |
| `vstop` = k | #7 D = max(k × ATR, distance from the planned entry to the candle's far side) | — |
| `rr` = (atr_mult, ratio) | #11 room from the entry to open ± atr_mult × ATR ≥ ratio × D | `reward` |
| `limit_d` = f | #12 stop-limit, limit = level ± max(f × D, 0.01); a fill beyond it → no trade (`ioc`) | (simulation: not filled) |
| `tod` = callable(m), `tod_min` | #2 cumulative volume 09:30 → m / prior-14 mean ≥ tod_min | `tod` |
| `depth` = callable(m) → (bid lots, ask lots), `depth_min` | #3 the trigger side's size ≥ depth_min | `depth` |

Planned entry (for D, shares, RR): the level for the touch entry; the confirming minute's close for #5 (the order
needs its size before it fills — recorded in the spec as 14.10 before any run).

Simulation: `_fill` handles `MKT` (the first minute at/after `at`, at its open) and `ioc` (a stop-limit whose fill
price is beyond the limit is cancelled). `simulate_ticks` handles `MKT` (the first round-lot trade of the minute) and
`ioc`.

## Task 2 — data helpers (`bot/alpaca.py`, cached, TDD with mocked `_get`)

- `minute_volumes(symbols, day)` → {sym: {minute: volume}} 09:30–16:00, one cache file per day (the T rule's 14
  prior sessions, for every ticker a top list needs).
- `news_symbols(prev, day)` → the set of symbols with an item from prev 16:00 to day 09:35, one cache file per day.
- `quote_full(sym, at)` → (bid, ask, bid size, ask size, age seconds) or None; cached like `quote_at`.

## Task 3 — the runner (`bot/zba_v2.py`)

1. Daily bars once per symbol over the range → prefilter per day plus the 14-day average dollar volume.
2. Opening bars per session (as `_zba_main`) → candidates → top 20 by relative volume and top 20 by the QR score.
3. Per day: minute bars of the union; minute volumes of the 14 prior sessions for the union; news set.
4. Per variant × ticker-day: the ticket (Task 1), DQ / L / N / Q5 outside `_zba`, bar-model simulation, costs.
5. Results per variant (stats, years, random p95, book); selection (14.4); tick-level re-run of the top 3; freeze to
   `docs/backtest/zba-v2-frozen.json`.
6. `--holdout`: reads the frozen file only, refuses to run without it, runs once, writes the report and CSVs.

Resumable: every fetch is cached under `.cache/alpaca`; a run that hits the time limit is re-started and walks the
cached days in seconds.

## Task 4 — the workflow (`.github/workflows/zba-v2.yml`)

`workflow_dispatch` (mode dev / holdout), restores and saves `.cache/alpaca` with `actions/cache` (always, also on a
timeout), a 330-minute step limit, re-dispatches itself while the run is not finished (a `done` marker), commits
`docs/backtest/` at the end. Never prints keys.

## Task 5 — report, review, PR

`docs/backtest/ticket-zba-v2-<date>.md` (Hebrew summary + tables, all 22 variants, every skip reason, #19 metrics) and
CSVs. A fresh reviewer on the most capable model over the whole diff; fixes; Hebrew report to the owner.
